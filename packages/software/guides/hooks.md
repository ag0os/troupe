# Guide: the builder hooks runbook

The builder runbook, for a Shepherd starting a Claude Code builder with these hooks:

1. Prepare through the installed binary, into the item's `runs/<run>/` directory; do not reinstall Troupe while the builder runs, since the settings name the installed package by path.
2. Copy the resolved base and exclusions from `prepare --json` into the brief; history writes are on unless an implementation coordinator holds the commit (a Shepherd is a project coordinator, so a Shepherd's builder commits on its branch); when off, set `history_writes` false and the brief says "leave the change uncommitted; the host commits after recheck". With history writes on the guard still denies `git push` unless `push_writes` is true; pull requests through `gh` or another client are not read by the guard, so the brief says pushes and pull requests stay with the host unless it grants them. The brief also carries the attribution lines, that a reserved stop opens the final message's first line with `Reserved decision stop: <decision>. <why the ruling is needed>`, and that a third Stop block means ending with a report that says "still failing after 3 attempts" and what remains.
3. Launch with `--settings <path>`; a one-shot builder runs `claude -p` with a finite `--max-turns`. An interactive builder has the counter and Claude's own cap of consecutive blocks, which this tool does not rely on. A builder whose Agent subagent runs in the background (the default in print mode on Claude Code 2.1.304) emits more than one `result` event and may pass Stop before the subagent ends: read the last `result`; step 5's recheck covers the rest.
4. After the first guarded tool call, confirm an `ALLOW` or `DENY` line in `hooks.log`. None means the run is unguarded: stop it and repair the launch. Each line reads `HH:MM:SS <hook> <tool or check> <file or scope> <n>ms <STATUS> <reason>`, the latency in milliseconds (`8ms`); a `DENY` reason names its rule and match, such as `history write git commit`.
5. Always run `recheck` when the session ends, however it ended: a run cut by `--max-turns` ends with no Stop event. Read `excluded` in its report before anything else: any entry takes the PR out of the grant. A resumed session inherits its counter; remove `runs/<run>/stop-<session_id>` to grant three more blocks. Record its findings as "post-run re-check" and the gate's as "stop gate", then run step 6's full gates; a successful Claude result is not acceptance, and changed system tests run there.

The guard denies shell writes to excluded paths as well as edits (redirections, `tee`, `sed -i`, `cp`, `mv`, `rm`, `install`, `ln`, `touch`, `truncate`, `unlink`, a copy or move into an excluded file's directory, a removal or move of a directory that holds an exclusion, a link whose source is excluded, a `find` that deletes or runs a command on `{}` under a path holding an exclusion, and what `find -exec` runs; a glob in the last segment is expanded), read lexically: a target holding an expansion, a deeper glob, a brace or a `~`, a write after `cd` or `pushd`, operands from `xargs`, a link made before the run, scripts and other writing programs are not read (the log says `shell writes not read`), and edits through the shell are not health-checked; the recheck covers excluded paths after the run. The push denial and the shell-write denial are lexical and bind a cooperative builder: `sh -c`, `eval`, a script and `gh pr create` (which pushes an unpushed branch) pass; the host's credentials are the boundary. A command whose program name or git option holds an expansion is refused unless both grants are on and nothing is excluded; the builder is told to spell it literally and run it again, which is not a hooks failure.

A diff that changes no test file and touches nothing a Contract covers or a named contract test selects passes with nothing run (the log shows PASS on zero checks): in a repository without Contracts the brief names the contract tests, and step 6's full gates run after the session either way.
